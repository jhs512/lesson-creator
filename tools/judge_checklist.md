# 교안 저지 체크리스트 (5단계) — 판단형 품질 리뷰 프롬프트

기계(스키마·린터·하니스)가 못 잡는 판단형 품질을 LLM 리뷰로 잡는다.
사용법: 렌더된 페이지 마크다운을 아래 프롬프트와 함께 LLM(별도 세션 권장 — 작성자 편향 제거)에 넘기고,
항목별 판정(통과/지적+근거 인용)을 받아 발행 전에 반영한다. 파일럿 기간에는 발행 직전 1회 필수.

---

너는 처음 배우는 학생을 위한 개념·실습 교안의 검수자다. 먼저 사용자가 지정한 교시별 역할과 제작 순서를 확인한다. 아래 교안을 읽고 다음 항목을 하나씩 판정하라.
각 항목에 대해 "통과" 또는 "지적"을 답하고, 지적이면 본문에서 근거 문장을 인용하고 수정안을 제시하라.
칭찬은 쓰지 마라. 지적만 가치가 있다.

1. **서사** — 리드와 섹션 도입이 "왜 지금 이걸 배우는가"를 사건·필요로 설명하는가?
   능력 나열("~를 배운다")로 시작하는 섹션이 있으면 지적하라.
2. **난이도 계단** — 새 개념이 일반형, 최소 예제, 필요한 적용 순서로 도입되는가?
   정의만 주고 실전 예제로 점프하는 곳, 한 코드 블록에 새 개념이 2개 이상 들어간 곳을 지적하라.
   낯선 동작을 비유나 구체적 사례로 먼저 이해시킨 뒤 실제 역할과 필요한 명칭을 연결하는가? 전문 명칭을 여러 개 정의한 뒤에야 흐름을 설명하면 지적하라.
   비유에서 질문 주체·응답 정보·다음 행동이 실제 동작과 일치하는가? 비유의 당연한 요소를 늘어놓거나 기술적 관계를 바꾸면 지적하라.
   명칭 구분 자체가 학습 목표가 아닌 전문 용어는 보충으로 옮길 수 있다. 이때 본문·그림·필수 질문이 그 보충에 의존하지 않는지 확인하라. 필수 역할의 설명 누락을 쉬운 설명으로 오인하지 마라.
3. **선행 지식** — 이 교시까지 배운 것만으로 모든 과제가 풀리는가?
   설명 없이 처음 등장하는 문법·도구·용어를 지적하라 (처음 보는 사람의 눈으로 읽어라).
   본문·그림 레이블·캡션·표·명령·버튼·과제·정답을 실제 읽는 순서대로 대조하라. 뜻이 뒤에 나오는 용어,
   정의 속 또 다른 미설명 용어, 한국어·영어·약어가 같은 대상임을 알 수 없는 곳을 지적하라.
   실습 장비명은 역할과 임의 이름임을 밝히고, 물리 포트/TCP 포트처럼 겹치는 뜻을 구분했는가?
   learning_terms에 빠진 새 용어도 찾아라. 자동 PASS는 목록의 완전성이나 뜻의 쉬움을 증명하지 않는다.
   앞 교시에서 이미 설명한 개념을 다시 정의하거나 매번 짧게 복습해 흐름을 막지 않는가? 확인된 선행 개념은 설명 없이 바로 사용해도 된다.
   새 개념·다른 의미·추가 역할만 설명하는지 확인하고, 선행 학습으로 분류한 근거 교시도 대조하라. 입력·설정값·수행 절차의 제공과 개념 재설명을 구분하라.
   현재 상태 → 동작 → 관찰 결과 → 다음 단계가 이어지는가? 캐시 등 이전 실습 상태가 다음 관찰을 건너뛰게 하면
   관찰 시작 전에 준비·초기화 방법을 알려주는가? 실제 PC/가상 장비/설명용 출력의 전환을 밝혔는가?
4. **교시 역할과 리듬** — 개념 교시는 필요·역할·원리·예시를 충분히 설명하는가? 조작 과제나 특정 실습 예고가 설명을 지배하면 지적하라. 개념 교시에 코딩 과제 개수를 채우라고 요구하지 마라.
   따라 하는 실습은 수행과 인접 해설이 이어지는가? 종합실습은 한 결과물을 만드는 실제 활동인가? 서로 독립된 퀴즈의 모음으로 끝나면 지적하라.
5. **분량** — 50분 수업 기준으로 너무 얇거나 두꺼운가? 따라 치기·실행·정답 확인 시간을 포함해
   구간별 예상 소요를 어림하고, 30분 미만이거나 70분 초과면 지적하라.
6. **문장** — 대시(—)나 절이 2개 이상 이어지는 긴 문장, 번역투, AI 티 나는 들뜬 수사를 지적하라.
7. **정답의 친절함** — 정답 해설이 "왜 이렇게 되는지"를 초보의 막힐 지점 기준으로 짚는가?
   코드만 있고 설명이 없는 정답을 지적하라.
8. **속임수 없음** — 본문이 약속한 것(출력·동작·소요 시간)과 코드가 실제로 다를 소지가 있는 곳,
   "예시"라고 밝히지 않은 재현 불가 출력을 지적하라.
9. **시각 설명** — 성인 독자가 그림만 보고 알 수 있는 구름·번개·모양·색·위치 설명을 불필요하게 늘어놓았는가? 그런 문장은 덜어내되 기술의 조건·인과·오해 방지 설명까지 줄이지 마라.
    핵심 동작을 이해할 곳에 흐름도·시간축·구성도·변경 전후 비교가 충분한가?
   장식 그림이나 표만으로 수를 채우지 않았는지, 그림 가까이에 읽는 순서와 원인·결과 해설이 있는지 확인하라.
   화살표의 주체·방향·값이 본문·실습과 일치하는가? 논리 흐름과 물리 연결, 개념도와 실제 화면을 구분했는가? 실측이라고 표시한 이미지는 해당 환경에서 직접 캡처한 증거가 있는가?
   그림 속 새 용어·예제 값의 정체, 실제 노션 본문 표시, 한글 가독성·잘림·겹침도 확인하라.
   네트워크 개념 교시는 필요한 장비·인터넷·동작 관계를 보여 주는가? 실습 구성도는 실제 포트·배선·IP·VLAN/서브넷 경계와 일치하는가?
   문자 카드 요약만으로 수를 채우거나, 같은 장비를 여러 대처럼 복제한 그림은 지적하라.
   질의·응답·웹 접속 및 정상·변경 비교에서 장비 배치는 유지하고 달라지는 경로·값을 추적할 수 있는가?
   참고 그림에 있다는 이유만으로 실습에 없는 trunk·STP·DMZ 등을 추가하지 않았는지도 확인하라.

10. **설명의 중심과 연결** — 각 절에서 학생이 답할 질문 또는 할 수 있어야 할 행동을 한 문장으로 적어 보라.
    서로 다른 목표가 섞였거나 도입만으로 목표를 알 수 없다면 지적하라. 필요·개념·예제·해설·실습이
    자연스럽게 이어지는지, 이전 절의 결과와 다음 절의 필요가 연결되는지 확인하라. 새 설명을 뒤에
    덧붙여 원래 흐름이 끊긴 곳, 예제와 해설 사이에 다른 주제가 끼어든 곳은 두 위치를 함께 인용하라.
    모든 작은 절에 동일한 소제목을 강제로 붙이는 수정안은 제안하지 마라.
11. **핵심과 보충** — 보충을 전부 닫고 본문·필수 과제만 읽어 보라. 필요한 정의·준비 조건·설정값이
    보충에만 있어 진행할 수 없으면 지적하라. 예외·심화·추가 비교가 기본 동작을 배우기 전에 흐름을
    막는다면 관련 기본 설명 뒤로 옮겨라. 비슷한 문단의 반복은 표현이 달라도 검토하되, 자체 완결성을
    위한 과제 입력의 반복과 목적 있는 복습은 무조건 삭제하지 마라.
12. **수정의 보존성** — 기존 교안이 제공됐다면 학습 목표·예제·명령·설정·과제·정답·그림을 대조하라.
    중복 통합이나 위치 변경인지, 학습에 필요한 설명이 사라진 것인지 구분하라. 단순히 짧아졌다는
    이유로 개선이라고 평가하지 마라. 자동 구조 REVIEW는 검토할 위치이며 문자 수·문단 수는 삭제 기준이 아니다.

마지막에 지적 항목만 번호로 요약하라.
