# 개념과 실습 교안 만들기

처음 접하는 사람이 글과 그림을 읽고 실습을 시작해 결과까지 확인할 수 있는 교안을 만든다. 특정 기관·날짜·Notion 워크스페이스에 종속되지 않는다. 사용자가 정한 과목, 학습 시간, 기존 교안과 수정 범위를 따른다. 예제의 Day 3 DNS 구성은 참고 자료이며 다른 수업의 필수 교육과정이 아니다.

## 작업 시작

1. 원본 교안, 각 교시의 역할(개념 설명·따라 하는 실습·종합실습), 이번 시간의 결과물, 이미 배운 내용, 실습 환경을 확인한다. 기존 교안 수정은 사용자가 지정한 범위 안에서 진행하고 다른 일차까지 자동으로 확장하지 않는다.
2. 교안 구성에는 [교안 구성과 실습 설계](references/lesson-design.md)를 읽는다. 새 용어·그림을 만들거나 보강할 때는 [용어와 시각 자료](references/terms-and-visuals.md)를 함께 읽는다.
3. 작성·검증·발행에는 [검증과 Notion 반영](references/validation-and-publishing.md)을 따른다. 새 교안은 JSON 원본을 만들고, 기존 교안은 가능한 경우 원본과 실제 저장 내용을 함께 갱신한다.

## 핵심 기준

- 사용자가 정한 개념 교시와 실습 교시의 구분을 먼저 지킨다. JSON의 `lesson_role`은 `concept`, `guided_practice`, `integrated_practice`로 명시한다. 개념 교시에 코드·GUI 조작·도전 과제를 일정 개수 채우도록 요구하지 않는다.
- 마무리 평가의 이름·형식·문항 수는 사용자의 최신 요청을 따른다. ‘마지막 도전’을 ‘점검문제 10개’로 바꾸라는 요청이면 이전 도전과 되새김 묶음을 교체한다. 각 문항은 4지선다·단일 정답으로 구성하고, 문항별 토글 안에 질문과 선택지를, 그 안의 별도 ‘정답·해설 보기’ 토글에 정답과 선택지별 해설을 둔다. JSON에는 `checkpoint_count: 10`, `checkpoint_question` 요소 10개를 쓰고 `require_final_challenge`를 제거하며 `review`는 빈 목록으로 둔다. 번호는 1부터 이어지고 토글 제목에는 답을 노출하지 않는다. 해당 교시의 필수 본문만으로 풀 수 있어야 하며 선택 보충·실습 조작을 필수 지식으로 묻지 않는다. 이 형식은 요청된 교시에만 적용한다. 다른 요청에서 마지막 도전을 유지해야 한다면 `require_final_challenge: true`와 마지막 `task_type: challenge`를 사용한다.
- 개념 교시는 일상 사례의 필요·역할·원리·동작 경로를 자세히 설명한다. 특정 실습 장비의 예고가 전체 설명을 지배하지 않게 한다. 실습 교시에는 실제 환경의 수행 순서와 확인할 값을 붙이고, 종합실습은 배운 동작을 연결해 하나의 결과물을 완성하게 한다.
- 그림은 학습 역할에 맞게 고른다. 개념 설명에는 관련 네트워크 예시를 검색해 참고하고 구름·라우터·서버·연결 기호로 원리를 설명한다. 실측이 요청된 실습 교시에는 해당 환경의 실제 캡처를 사용한다. 사용자 지정 제작 순서와 나중에 하기로 한 촬영 일정도 유지한다.
- 사용자가 두 흐름의 50분 수업을 요청하면 설명 10분 → 같은 흐름의 사례 읽기 10분 → 두 번째 흐름 설명 10분 → 사례 읽기 10분 → 점검문제 10분으로 설계한다. 시간표만 붙이지 말고 설명에는 핵심 관계를, 읽기에는 구체적 상황·값·해석·실패 비교를 배치한다. 늘릴 때는 새 사례의 추론을 보강하고 이미 설명한 정의를 반복해 분량을 채우지 않는다. JSON의 `lesson_format: two_flow_50`, 교시 `session_minutes: 50`, 절의 `phase`·`flow`·`minutes`로 검수한다. 다른 수업에 자동 강제하지 않는다.
- 공인 IP를 요청한 개념 예시는 공식 자료로 확인한 공인 주소를 사용하고, 실제 서비스 사실과 가정한 매핑·장애를 구분한다. 본문·그림·문제·정답의 주소를 함께 점검한다. 사설 주소를 인터넷에서 그대로 사용하는 것처럼 설명하지 않는다. `public_ip_examples: true`는 이 요청이 적용되는 교시에만 지정하고, 내부망 실습의 사설 IP까지 무조건 바꾸지 않는다.
- Packet Tracer의 고정 포트 표와 복사할 설정 명령을 제공하는 교안에서는 수동 케이블 선택 → 첫 장비와 포트 → 두 번째 장비와 포트를 명시한다. 사용자 최신 선택이 우선이다. 자동 연결을 명시적으로 요청한 경우에만 자동 선택 결과를 확인해 명령에 맞춘다. 연결 순서가 포트 지정을 대신한다고 설명하지 않는다. 포트 배치의 이유와 연속 range 사용 조건도 구분한다.
- 순차 설명은 `numbered_list` 또는 Notion의 실제 번호 목록을 쓴다. 한 문장 안에 ①②③을 끼워 넣지 않는다.

- 앞 교시에서 이미 설명한 개념은 다시 정의하지 않고 바로 사용한다. 매번 짧게 복습하는 문장도 의무로 넣지 않는다. 새 개념, 같은 말의 다른 의미, 이번에 새로 추가되는 역할만 설명한다. 실습에 필요한 입력·설정값·수행 절차는 제공한다.
- **필요 → 역할 → 쉬운 뜻 → 실제 예 → 동작 → 확인 결과**를 잇는다. 용어집을 뒤에 붙여 첫 사용의 설명을 대신하지 않는다. 그림·표·버튼·명령에 먼저 등장하는 말도 첫 사용이다.
- 지문은 `~이다/~한다`와 `~살펴보자/~해 보자`를 자연스럽게 섞는다. 한 절의 중심 질문이나 학습 목표를 하나로 잡고 도입에서 밝힌다. 목표가 달라지면 절을 나누고 실제 제목과 목차를 맞춘다.
- 자세한 설명은 핵심·예제 해설·보충의 위계로 정돈한다. 필요한 이유 → 개념 → 예제 → 인접 해설이 이어지게 하고 실습 교시에서는 수행으로 연결하되 모든 작은 절에 같은 소제목을 반복하지 않는다. 기본 설명 뒤의 `supplement`에 예외·심화·추가 비교를 모으고, 이를 닫아도 필수 과제를 시작할 수 있게 한다.
- 보강할 때 설명을 끝에 계속 덧붙이지 않는다. 반복되는 설명은 한곳에 합치고 절 사이에 다음 내용이 필요한 이유를 연결한다. 분량 자체를 줄이는 것을 목표로 삼지 말고 학습 목표·예제·설정값·실습·정답이 남았는지 원문과 대조한다.
- 학생이 강사의 추가 설명이나 다른 페이지 없이 과제를 시작하고 성공 여부를 알 수 있게 입력·준비물·행동·예상 결과·정답을 제공한다. 실행용 코드 블록은 필요한 정의와 데이터를 포함한다.
- 성인 비전공자를 기준으로, 전문 지식은 쉽게 설명하되 일반 상식이나 눈으로 바로 알 수 있는 그림 모양까지 풀어 쓰지 않는다. 자세함은 원리·조건·원인과 결과·실패 해석에 쓴다.
- 낯선 동작은 익숙한 비유나 구체적 사례로 먼저 설명하고 실제 역할·동작과 연결한다. 전문 명칭을 여러 개 정의한 뒤 흐름을 시작하지 않는다. 이해·실습에 필요한 이름은 쉬운 설명과 함께 소개하고, 명칭 구분 자체가 목표가 아니면 보충으로 옮긴다. 보충을 닫아도 본문·그림·필수 질문을 이해할 수 있어야 한다.
- 시각 자료는 실제 대상·연결·상태 변화가 보이게 한다. 글을 상자에 나눈 그림만으로 동작 설명을 대신하지 않는다. 그림 속 명칭과 값은 본문·실습과 맞춘다.
- 자동 검사와 읽기 검수를 함께 한다. 하네스 통과는 선언한 용어의 순서와 일부 코드 출력에 관한 결과이며, 용어 목록의 완전성이나 설명의 쉬움을 증명하지 않는다.

## 함께 사용하는 파일

전체 `lesson-authoring-toolkit` 저장소를 복제해 사용하는 것을 권장한다. 이 스킬이 저장소의 `.agents/skills/lesson-page/`에 있으면 세 단계 위가 저장소 루트다. 아래 명령은 그 루트에서 실행한다.

| 경로 | 역할 |
| --- | --- |
| `tools/lesson_schema.py` | JSON 구조와 과제 형식 정의·검증 |
| `tools/lesson_render.py` | JSON을 Notion용 Markdown으로 변환 |
| `tools/lesson_harness.py` | Python 출력·용어 첫 사용·필수 본문의 보충 의존 검사와 구조 REVIEW |
| `tools/lesson_structure.py` | 목차 대응·중복 문단·보충 위치 검토, 보충을 닫은 본문의 용어 검사 |
| `tools/lesson_term_flow.py` | 용어 순서 검사, SVG의 실제 글자 추출 |
| `tools/lesson_lint.py` | Markdown 형식·표현 오류 검사 |
| `tools/judge_checklist.md` | 선행 지식·설명 흐름·실습·그림 읽기 검수 |
| `tools/render_lesson_preview.py` | 로컬 HTML 미리보기 생성 |
| `tools/mkedit.py` | 한국어 원문에서 Notion 부분 수정 인자 생성 |
| `tools/build_network_diagrams.py` | 예제 네트워크 구성도의 SVG·PNG 생성 |
| `examples/day3/` | 용어 소개·그림·관찰 과제를 포함한 교안 예제 |

스킬 폴더만 별도로 설치했다면 위 도구가 자동으로 설치되지는 않는다. 전체 저장소 위치를 확인하거나 도구·예제를 작업 프로젝트로 함께 가져온다. 도구가 없으면 검수 지침으로 초안을 작성할 수 있지만, 실제로 실행하지 않은 검사를 통과했다고 보고하지 않는다.

Notion 게시 기능이나 인증 정보는 이 스킬에 포함되지 않는다. 사용자의 연결된 Notion 도구와 확인된 대상 페이지를 이용해 요청받은 변경을 반영한다. 로컬 생성 완료와 외부 게시 완료를 구분한다.
