# 교안 구성과 실습 설계

이 문서는 한국어 실강용 기본 템플릿이다. 사용자가 정한 수업 시간·평가 방식·기존 구조가 있으면 그 맥락에 맞춘다. 예제에 등장하는 특정 일차, 기관명, 프로그램 파일명을 새 수업의 전제로 삼지 않는다.

## 독자와 문체

- 네트워크·코딩 배경지식이 없는 독자를 기준으로 한다. 처음 배우는 문법과 새로운 도메인 상황을 한꺼번에 요구하지 않는다.
- 서술은 `~이다/~한다`, 함께 해 보는 안내는 `~알아보자/~해 보자`로 쓴다. 소제목은 `DNS 응답 살펴보기`처럼 동작이 보이게 짓는다. 코드 출력은 자연스러운 시스템 메시지나 존댓말을 그대로 쓴다.
- 순서가 있는 설명은 실제 Markdown 번호 목록을 사용한다. `numbered_list`는 한 항목을 한 줄로 렌더한다. 문장 중간의 동그라미 숫자 나열은 쓰지 않는다.
- 수업 자료가 읽기 전용인 경우 페이지에 직접 적거나 체크하게 하지 않는다. 기본 템플릿은 일반 불릿을 쓰며 체크박스·콜아웃·페이지 아이콘을 넣지 않는다. 중요도 표시가 필요하면 `✅` 필수, `❗` 실무 빈출만 사용한다.
- 비유는 개념 하나를 돕는 짧은 설명에 쓴다. 수업 전체를 끌고 가는 확장 비유, 과한 수사, 볼드 남발은 피한다.
- 실제 규칙과 수업의 약속을 구분한다. 예제 IP, 서비스 응답 필드, 로그 형식, 장비 이름이 모든 환경에서 같다고 오해하게 하지 않는다.

## 교시의 역할을 먼저 정하기

| JSON 값 | 중심 활동 | 확인 방식 |
| --- | --- | --- |
| `concept` | 개념·역할·원리를 문장과 예시 그림으로 이해 | 짧은 예측·설명 질문, 선택 보충 |
| `guided_practice` | 설정·실행·관찰·복구를 따라 수행 | 단계별 입력값과 실제 화면의 확인 위치 |
| `integrated_practice` | 배운 동작을 스스로 연결해 하나의 결과물 완성 | 시작 조건·요구사항·실제 증거·복구·보고서 |

개념 교시에 실습 과제 4–7개, 코드 8블록, 에러 시연 2개, 마지막 코딩 도전을 강제하지 않는다. 짧은 이해 확인은 `predict` 과제로 쓸 수 있지만 실제 프로그램 실행으로 이어지게 만들 필요는 없다. 익숙한 공개 웹사이트의 이름 조회를 설명하면서 처음부터 특정 인트라넷 구성만 반복하지 않는다. 개념을 충분히 설명한 다음 실습 교시에서 단순화한 내부망 모델을 소개한다.

종합실습은 서로 무관한 문제 여러 개의 모음으로 대신하지 않는다. 정상 기준 → 조건 변경 → 관찰 → 원인 구분 → 복구 → 결과 정리처럼 한 환경과 하나의 결과물로 연결한다. 학생이 실제로 관찰한 값과 교안의 예상 결과를 구분하고, 시작 파일이 없을 때의 대체 준비는 끝까지 완료할 수 있게 한다.

`lesson_role`을 생략한 기존 코딩 교안에는 이전 과제 개수 규칙이 남는다. 새 원본은 역할을 선언하고 린터에 같은 `--role` 값을 전달한다. 사용자의 수업 목표를 충족하지 못한 교안을 통과시키려고 역할을 바꾸지 않는다.

## 실습 교시의 기본 흐름

1. **리드**: 앞 활동의 한계나 구체적 상황에서 출발한다. 이번 시간에 무엇을 해결할지 이어 쓴다. 제목 기본형은 `N교시. 주제 — 설명`이다.
2. **미니 목차**: 실제 소제목을 3~6개로 안내한다.
3. **미리보기**: 오늘 얻을 코드·명령 결과·구성도를 보여 준다. 새 용어가 많은 미리보기는 필요한 이름을 먼저 소개하거나 뒤로 옮긴다.
4. **개념과 작은 과제**: 문제 상황, 쉬운 정의, 최소 예제, 실습 적용을 이어 쓴다. 긴 설명을 몰아놓지 않고 관찰·실행·예측을 사이에 둔다.
5. **스스로 완성하는 도전**: 준비된 시작 틀의 핵심 동작을 채우게 한다. 앞 과제들은 완성 코드를 저장·실행·관찰하는 방식으로 학습 부담을 조절한다.
6. **추가 과제**: 빨리 끝난 학생을 위한 선택 과제를 토글로 둔다. 필수 개념을 여기에서 처음 가르치지 않는다.
7. **챙겨 가기**: 개념·한 줄 요약·다시 쓰는 상황을 3~5행으로 정리한다.
8. **되새김**: 배운 내용을 말로 설명하는 질문 3개를 둔다.

새 문법은 **일반형 → 가장 단순한 예 → 실제 수업 데이터 적용** 순서로 설명한다. 해석을 주석으로 다시 보여 줄 때는 실행용 원본과 구분한다. 오류 사례는 학생이 정상 동작을 먼저 해 본 뒤 배치하고, 실제 오류 메시지와 뜻을 함께 보여 준다. 네트워크·GUI 수업에서는 Python 문법 오류를 억지로 넣지 말고 해당 환경의 실패 결과와 진단을 설명한다.

실습 교시가 50분이라면 설명을 뺀 시간을 학생이 실행·조작·변형·확인하는 데 충분히 쓰는지 어림한다. 말로만 답하는 퀴즈를 실습 시간으로 세지 않는다. 실습을 코드 작성으로 한정하지 않는다. 네트워크 장비 배치·설정·패킷 관찰도 손을 쓰는 실습이다. 5분 이상 걸리는 활동은 본문 속에 숨기지 말고 과제로 번호를 붙인다.

## 자세한 설명의 순서와 위계

절을 쓰기 전에 학생이 그 절에서 이해하거나 확인할 중심 질문을 한 문장으로 정한다. 도입에서 그 질문과 현재 활동의 관계를 밝힌 뒤, 필요한 개념·작은 예·예제 해설·실습으로 이어 간다. 이 순서는 설명을 구성하는 기준이며 모든 절에 `필요/개념/예제/해설/실습` 소제목을 반복하라는 뜻이 아니다.

기본 동작을 이해하는 데 필요한 정의·조건·설정·예상 결과는 본문에 둔다. 예외, 심화 원리, 추가 명령 비교는 해당 기본 설명 뒤의 보충 영역으로 묶는다. JSON에서는 `{"kind":"supplement","title":"구체적인 보충 제목","body":[...]}`를 쓰면 접을 수 있는 영역으로 렌더된다. 보충에는 중첩 보충이나 필수 과제를 넣지 않는다. 보충을 닫고 본문과 필수 과제만 읽어도 진행할 수 있어야 한다.

예제 바로 앞에서는 무엇을 볼지 알려 주고, 바로 뒤에서는 실제 값이나 단계가 왜 그렇게 되는지 설명한다. 그 사이에 다른 주제의 비교나 다음 단원 설명을 끼우지 않는다. 긴 미리보기의 새 용어는 관련 절로 옮겨 소개하고, 미리보기 자체는 결과물과 전체 흐름을 짧게 안내하는 데 쓴다.

같은 역할·주의사항을 되풀이했다면 가장 필요한 위치에 설명을 합친다. 다음에 다시 사용할 때는 현재 활동에 필요한 한 문장만 상기한다. 절이 바뀔 때에는 앞에서 확인한 것과 이제 확인할 것을 연결한다. 한 절이 여러 질문에 답하게 됐다면 설명을 줄이기 전에 절과 순서를 다시 설계한다.

수정 전후의 학습 목표·예제·명령·설정값·과제·정답·그림을 대조한다. 통합한 중복과 옮긴 보충을 설명할 수 있어야 하며, 길이나 문단 수를 맞추려고 필수 내용이나 유용한 예제를 지우지 않는다. 시간표를 남긴다면 실제 활동과 맞추고, 모든 교시에 똑같은 설명·해보기 표를 복제하지 않는다.

## 과제를 혼자 완주할 수 있게 만들기

모든 필수·추가·도전 과제는 다음을 갖춘다.

- **주어진 것**: 입력 데이터, 파일 내용, 시작 코드, 장비 상태, 필요한 준비 방법.
- **할 일**: 무엇을 입력·설정·실행·비교할지 구체적 동사로 설명.
- **성공 판정**: 목표 출력 또는 화면에서 확인할 값. 시각·주소처럼 달라지는 값은 변동 조건을 설명.
- **정답과 이유**: 실행 가능한 정답 또는 관찰별 예상 결과. 정답이 여러 가지면 그 사실과 예시 답을 제시.

`앞 과제의 함수를 가져오자`, `아까 만든 서버에 추가하자`만으로 필요한 정보를 생략하지 않는다. 복습 출처 표기를 지워도 지문만으로 풀 수 있어야 한다. 짧은 입력 파일은 문제 안에 전문을 싣고 저장할 이름과 위치를 알려 준다. 대용량 자료는 접근 가능한 자료 파일을 제공한다. 전날 수업을 끝내지 못한 학생도 시작할 수 있게 한다.

실험형 과제는 관찰 질문마다 예상 결과를 붙인다. 예측형은 생각할 시간을 준 뒤 정답 토글에서 확인하게 한다. 서버를 만드는 과제에는 요청을 보내 테스트하는 반대편 코드나 구체적인 검사 방법도 제공한다.

## 코드와 시작 틀

- 실행용 예제·과제·정답은 각 블록을 새 파일에 붙여 실행할 수 있는 완전체로 쓴다. 필요한 import, 함수, 입력 데이터, 파일 읽기를 포함한다. 파일이 필요하면 내용이나 제공 위치와 저장 절차를 명시한다.
- 실행이 목적이 아닌 미리보기·주석 해석·교체할 한 줄은 그 목적을 밝힌다. 의도된 오류 예제는 본문에서 설명한 오류가 단독 실행에서도 나야 한다.
- 체험 과제는 바뀐 값이 이미 반영된 완성 코드를 제공한다. 여러 곳을 지우고 옮기게 하는 편집 지시로 학습 목표를 흐리지 않는다.
- 도전은 `요구사항 + 시작 틀 + 목표 출력 + 정답`으로 만든다. 준비 코드·입력·보조 함수는 제공하고 핵심 학습 동작만 1~3곳 비운다. 빈 자리는 가짜 출력 대신 할 일을 적은 주석으로 둔다.
- 시작 틀은 정답의 부분집합이다. 틀의 줄을 지우거나 고칠 필요 없이 채우기만 하면 완성되게 한다. 그대로 실행해도 문법 오류가 나지 않게 준비 줄을 둔다.
- 채우는 구간과 정답의 해당 구간은 같은 들여쓰기의 `# <<<<<<<<<<<< 수정 시작 <<<<<<<<<<<<`, `# >>>>>>>>>>>> 수정 끝 >>>>>>>>>>>>` 경계 주석으로 대응시킨다. 채우기 주석에는 그 자리에서 할 일을 완전하게 설명한다.
- 필요한 보일러플레이트는 주고 호출·분기·누적·출력 등 학습 목표에 해당하는 동작을 학생 몫으로 남긴다. 수업 수준에 맞게 분량을 정한다.

## 표지·종합 실습·자료 페이지

표지는 오늘의 문제와 결과물, 교시별 목표, 준비물을 간결하게 안내한다. 기존 Day 표지나 하위 페이지가 있으면 그 구조를 활용한다. 새 자리 페이지가 이미 있다고 가정하지 않는다.

종합 실습은 새 개념을 추가하기보다 이미 배운 동작을 연결한다. `목표 → 준비물 → 진행 방법 → 목표 확인 → 확장 활동`으로 구성하고, 설정·서버·입력 파일까지 현재 페이지에서 얻을 수 있게 한다. LLM 활용이 수업 목표에 포함돼 있으면 직접 만든 결과와 LLM이 만든 결과를 비교하고 실제 출력으로 확인하는 활동을 넣는다.

자료 페이지는 실습에 필요한 데이터 파일을 담는다. 연결 설명·설정 방법·흐름도·문제 해설은 해당 교시에 둔다. 나중 내용을 미리 가리킬 때는 `다음 시간`, `마지막 종합 실습`처럼 흐름에 맞는 표현을 쓰고, 불필요한 일차 번호 예고를 줄인다.

## 보강 후 읽기

질문에 답을 추가했다면 절을 다시 나눈다. 한 절에 주제가 쌓이지 않았는지, 목차가 실제 제목과 맞는지, 절 끝이 다음 동작으로 이어지는지 본다. 설명을 코드 앞에 계속 쌓기보다 짧게 소개하고 직접 관찰한 뒤 필요한 설명을 이어 쓴다.

요구사항·힌트·채우기 주석에서 `교시`, `과제 `, `Day `를 검색한다. 참조를 지웠을 때 못 푸는 문제는 필요한 내용을 현재 페이지에 채운다.
