# 용어와 시각 자료

## 용어의 첫 사용 확인

본문만 읽지 말고 미리보기·그림 글자·캡션·표·명령·버튼·과제·정답을 실제 표시 순서대로 살펴본다. 새 용어가 나오기 전에 어떤 상황에서 어떤 역할이 필요한지 알려 준다. 정의 안에 다른 미설명 용어가 있으면 먼저 풀어 쓴다.

정의 기본형은 `> **용어(English)** — 쉬운 뜻.`이다. 설명은 용어를 바꿔 말하는 데 그치지 말고 수업에서 하는 일을 말한다. 예를 들어 인트라넷은 조직 안에서 사용하는 내부망이라는 뜻을 소개한 뒤, 이 실습의 `IntranetServer`는 내부 웹 화면을 제공하는 서버에 붙인 이름이라고 연결한다. 인트라넷 서버가 언제나 웹 서버인 것처럼 일반화하지 않는다.

한국어·영어·약어가 같은 대상임을 연결한다. `PC0`, `IntranetServer` 같은 실습 이름은 임의 이름임을 밝힌다. IP·도메인·포트 값은 누구의 무엇인지 소개한다. 케이블을 꽂는 물리 포트와 프로그램 통신을 구분하는 포트 번호처럼 같은 말의 다른 뜻을 구분한다.

이전에 배운 말은 지금 필요한 역할만 짧게 상기한다. 매 교시 앞에 용어집을 반복하지 않는다. 학습 목표에 필요 없는 전문명은 더 가르치기보다 덜어낸다.

실습은 **지금 가진 상태 → 할 동작 → 보일 결과 → 다음에 할 일**로 연결한다. 이전 실습의 캐시·설정 때문에 관찰이 달라진다면 정상 관찰 전에 준비·초기화 방법을 알려 준다. 실제 PC, 가상 장비, 설명용 출력 사이의 전환도 밝힌다.

## 검사 메타데이터

새 교안과 용어를 보강하는 교안은 JSON의 `learning_terms`에 핵심 용어·별칭·실제 소개 문장을 선언한다.

```json
{
  "learning_terms": [
    {
      "term": "인트라넷 서버",
      "aliases": ["IntranetServer"],
      "introduced_by": "이 실습에서는 조직 안에서 사용하는 웹 화면을 제공하는 서버를 인트라넷 서버라고 부른다."
    }
  ]
}
```

이 조각은 필드 형식 예시다. `introduced_by`의 정확한 문장이 이미지 이전의 보이는 본문에도 있어야 한다. 메타데이터에만 설명을 넣지 않는다. 이 예시 문장 앞에서도 `조직 안의 망`과 `서버`의 뜻을 학생 수준에 맞게 소개해야 한다.

모든 표시 이미지에 실제 글자 목록인 `image.text_content`를 넣는다. SVG는 `tools/lesson_term_flow.py`의 `svg_text_content(path)`로 `<text>` 내용을 추출한다. 화면 캡처·윤곽선 글자는 보이는 문자를 옮겨 이미지와 대조한다. 파일명으로 추측하거나 검사할 용어만 일부 옮기지 않는다.

하네스는 소개 누락, 첫 사용보다 뒤에 있는 소개, 이미지 글자 목록 누락을 검사한다. 선언한 용어만 검사하므로 목록의 누락은 사람이 찾아야 한다. 같은 문단 안의 설명 순서·쉬운 뜻·교시 사이의 선행 지식도 읽기 검수 대상이다. FAIL을 없애려고 별칭이나 이미지 글자를 삭제하지 않는다. `learning_terms` 없는 교안의 SKIP를 용어 검사 통과라고 보고하지 않는다.

## 그림이 설명해야 할 것

핵심 동작은 분야의 실제 대상과 구조가 보이는 그림으로 설명한다. 순서·분기는 흐름도, 시간 변화는 시간축, 공간·연결은 구성도, 원인에 따른 결과는 전후 비교를 쓴다. 문장을 상자에 옮긴 요약도나 장식 그림으로 수를 채우지 않는다.

그림은 관련 개념 가까이에 둔다. **그림을 읽는 순서 → 왜 그렇게 움직이는지 → 실습 화면·코드에서 확인할 값**을 인접 해설로 연결한다. 화살표에는 누가 누구에게 무엇을 보내는지 표시한다. 설명용 그림·설정 안내도·실제 화면 캡처를 캡션에서 구분한다.

정확한 글자·값·연결이 필요한 그림은 수정 가능한 SVG와 표시용 PNG를 함께 남긴다. 한글 글꼴, 본문 폭의 가독성, 글자·화살표 겹침, 잘림을 실제 렌더로 확인한다. 색에만 의존하지 않고 이름·단계 번호·선 모양을 함께 쓴다.

## 네트워크 그림의 기준

- PC·스위치·라우터·서버를 서로 알아볼 수 있는 장비 기호로 그린다. 실제 실습의 케이블·장비 포트·IP·VLAN 또는 서브넷 경계를 표시한다. 범용 카드 그림으로 실제 구성을 대신하지 않는다.
- 통신은 구성도 위에 방향·단계 번호·패킷 등을 얹어 보여 준다. 물리 배선과 논리 요청·응답 선을 구분한다. 실제로 하나인 스위치를 경로 설명 편의 때문에 두 대로 복제하지 않는다.
- 질의·응답·후속 접속, 정상·변경 상태 비교는 장비 배치와 배선을 유지한다. 해당 단계의 경로·전달 정보·값만 강조한다. 복잡하면 단계별 그림으로 나눈다. 생략한 장비나 조건은 밝힌다.
- 참고 그림에서는 장비 표현과 연결 방식을 배우되 수업에 없는 trunk·STP·DMZ 등을 모양을 맞추려고 끌어들이지 않는다. 공개 서비스와 내부 실습 모델도 구분한다.
- 주소나 동작 값은 본문과 같은 자료에서 가져온다. DNS 설명이라면 응답 패킷의 받는 주소, 답에 들어 있는 IP, 그 뒤 웹 접속의 목적지를 혼동하지 않게 구분한다.

## 포함된 이미지 제작 도구

`tools/build_network_diagrams.py`는 Day 3 DNS 예제의 장비 그림과 단계별 동작을 SVG·PNG로 생성한다. 범용 문장을 받아 모든 교과 그림을 자동 생성하는 도구는 아니다. 다른 실습에는 배치·주소·레이블·설명 코드를 바꾸고 실습과 대조한다.

저장소 루트에서 `python3 tools/build_network_diagrams.py --help`로 현재 옵션을 확인한다. 출력 폴더는 `--out`, 사용 가능한 한글 글꼴 파일은 `--font`로 지정한다. 생성된 SVG를 바꾸었으면 PNG와 `text_content`도 함께 갱신한다. 도구가 만든 결과라도 기술적 정확성과 가독성은 별도로 확인한다.

Notion에 반영할 때 로컬 경로만 적고 완료로 처리하지 않는다. 사용자 환경의 업로드 기능으로 이미지 블록을 만들고 게시 후 위치·캡션·인접 해설을 재확인한다.
