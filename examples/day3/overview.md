## 이름을 입력한 뒤 무슨 일이 일어날까
평소처럼 주소창에 `naver.com`을 입력했다고 생각해 보자. 내 컴퓨터는 어떻게 접속할 곳을 알아내고, 인터넷을 거쳐 그곳의 웹페이지를 받아 올까? 오늘은 이 과정을 먼저 개념으로 이해한 다음 작은 네트워크에서 직접 확인한다.
DNS는 이름에 대응하는 주소 등의 정보를 찾아주는 체계다. 이름에 답하는 서버의 역할, 답을 찾아가는 순서, 받은 답을 잠시 저장하는 이유를 나누어 살펴보자.
1. 이름과 IP 주소가 왜 필요한지, DNS 조회와 웹 접속이 어떻게 이어지는지 이해한다.
2. 네임서버가 이름을 나누어 관리하고 리졸버가 담당자를 찾아가는 흐름을 이해한다.
3. 레코드의 뜻과 캐시·TTL, 응답이 달라졌을 때 살펴볼 근거를 이해한다.
4. 정상 네트워크를 직접 구성하고 이름 조회와 웹 접속을 확인한다.
5. 응답 주소를 바꿔 접속 대상의 변화를 관찰하고 정상으로 복구한다.
6. 두 장애 조건을 각각 재현해 원인을 구분하고, 실제 관찰값으로 복구 보고서를 완성한다.

## 준비와 결과물
1–3교시는 교안과 개념 그림을 읽으며 진행한다. 4–6교시는 Packet Tracer를 실행할 수 있는 PC와 보고서를 적을 편집기가 필요하다. 실습에 사용하는 내부 포털은 개념을 직접 확인하기 위한 별도의 작은 모델이다.
4교시의 정상 구성은 `day03_dns_normal.pkt`, 5교시의 비교 후 복구 상태는 `day03_dns_response_comparison.pkt`로 저장한다. 6교시에는 `day03_dns_integrated.pkt`와 `day03_dns_report.md`, 직접 캡처한 증거 이미지를 남긴다. 이 파일들은 학생이 실습하며 만드는 결과물이다.
